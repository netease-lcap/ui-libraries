## Why

业务中常见的「查询表单」需要在有限宽度内整齐排布表单项，并在同一视觉行内固定「查询 / 重置」等操作区；容器变窄时应自动减少列数，操作区始终靠右，且在按钮过多时允许单独换行仍保持右对齐。现有通用表单缺少针对该场景的约定式布局与行为规范。

## What Changes

- 为表单增加**查询表单**模式（如 `queryForm`）：与 **`layout` 取值分工**如下：
  - **`layout === 'grid'`（栅格展示）**：列数**仅**由用户 **`columns`** 决定，**不**根据宽度在 2/3/4 间切换；与视口/表单容器断点无关。
  - **`layout` 为其他值**（如行内、块级）且**开启查询表单**：在**表单自身可视宽度**（而非仅视口）上启用断点栅格，边界按**大于等于**归入更高档：
    - 宽度 **≥ 1200px**：每行 **4** 列；
    - **992px ≤ 宽度 < 1200px**：每行 **3** 列；
    - **宽度 < 992px**：每行 **2** 列。
- 增加**操作区域具名插槽**：在非 grid 的查询布局下，与表单项处于同一逻辑行时**整体靠右**；当操作区内内容在一行内放不下时，**整块操作区换到下一行**，且在新行上**仍靠右**对齐（grid + 查询同时开启时，列数不占断点；操作区与 grid 的相对关系由实现与 `columns` 网格约定，首版以实现为准）。
- 文档与 Storybook 示例需体现：`layout` 分支、断点与操作区换行（不要求改 Element Plus 上游 API，以本库封装层为准）。

## Capabilities

### New Capabilities

- `form-query-layout`: 查询表单与 `layout` 的组合规则、响应式栅格列数（仅非 grid）、固定 `columns`（grid）、操作具名插槽对齐与换行规则，以及与本库 `el-form` 封装的集成约定。

### Modified Capabilities

- （无）当前 `openspec/specs/` 下无既有规格；若后续在全局规格中登记表单行为，可再补充 delta。

## Impact

- 受影响：`el-form` 相关组件实现、样式（CSS/主题变量若需）、`api.ts` 中 `layout` / `queryForm` / `columns` / 具名插槽说明、Storybook 故事与文档。
- 依赖：非 grid 的查询布局需基于表单容器宽度观测（如 `ResizeObserver`）或等价方案；grid 模式继续沿用现有 `--el-form-columns` 等路径。
